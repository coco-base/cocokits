# Story language

Purpose: what a custom story may contain, how args, state and handlers behave, how catalog types keep the compiler and TypeScript in agreement, and the compile errors.

A custom story is one `<id>.story.tsx` with a default export of `defineStory`. Components are globals typed by the generated `jsx.d.ts`, so the file imports `defineStory` from `@cocokits/shared`, plus the constructs it uses (`state`, `derived`, `set`, `toggle`, `add`, `remove`, `when`, `each`, `form`, `reset` and the validators `required`, `email`, `minLength`, `maxLength`) in a second import from `@cocokits/story-compiler/language`. The compiler adds the imports of every component the story uses to the printed file. The compiler parses the file and never runs it.

```tsx
// packages/docs-stories/src/button/icon-only.story.tsx
import { defineStory } from '@cocokits/shared';

export default defineStory({
  title: 'Icon only',
  description: 'A button without text needs an accessible name.',
  render: () => (
    <Button aria-label="Add item">
      <svg viewBox="0 0 24 24" width="16" height="16" aria-hidden="true">
        <path d="M12 5v14M5 12h14" stroke="currentColor" stroke-width="2" />
      </svg>
    </Button>
  ),
});
```

| Allowed | Notes |
|---|---|
| `<Name …>` | Any component that has an `ApiDoc` for the framework (`<Name …>`, the PascalCase of its id). It may sit inside another component or element ([Several components in one story](./stories-and-scenarios.md#several-components-in-one-story)) |
| Native HTML and SVG elements, fragments `<>…</>` | Attributes use HTML names (`for`, `tabindex`, `stroke-width`) from one native vocabulary table in the compiler, which grows when a story needs a new one. `pre` and `textarea` are not in it: their white space is content, and the three frameworks read it differently. The `textarea` that the Textarea renders is a host only: a story writes `<Textarea maxlength={maxLength} />`, and the host takes `maxlength`, `minlength` and `rows` |
| Literal values: `a="x"`, `a={3}`, `a={true}`, bare `a` | Props, theme options and native attributes. Vue prints every component prop in kebab-case (`activation-mode`, `aria-label`; a native attribute keeps its HTML name) and a literal `true` on a boolean prop as the bare name (`open`, `disabled`, a model prop too); `false` stays `:open="false"` |
| Arrays: `a={['a', 'b']}` | Not in the language: an array literal is an `unsupported-syntax` error, so a prop typed as a list, a tuple or an object cannot be set from a story. The one exception is the initial value of a list model, `defaultValue={['Cake', 'Pizza']}` ([List models](#list-models)). A value of any other list is the theme's job (a documented custom property) or a prop the author sets in the app |
| `defaultChecked={true}` or `defaultValue="…"` on a component with a model (Checkbox, Switch, Radio, Input, Textarea) | The initial value of the model, named `default<Model>` after the model's semantic id ([playground-and-snippets.md](./playground-and-snippets.md#controls)). The user can change it afterwards. It takes a literal of the model's kind (a boolean for a checked model, a string for a value model). The model prop itself (`checked`, `value`) is not a prop of the story language; only a Checkbox or Switch takes `checked` as the controlled checked model (next rows). Angular prints `[checked]="true"` or `value="Ada"`, React `defaultChecked` or `defaultValue="Ada"`, Vue `model-value` (the bare name for `true`) or `model-value="Ada"`; on a root with a Vue `default<Model>` prop (Dialog, Popover, Tooltip, Select, Tabs) `default-open` or `default-value="account"` |
| `as="a"` on a component | Chooses another host element; the allowed tags come from the component's Angular selectors. A selector with no element (`[cck<Name>]`) takes its default element from the `defaultElements` of the component's meta, and `as` then accepts any element of the native vocabulary |
| Markup in a component attribute: `label={<Label for="email">Email</Label>}`, or a fragment `hint={<>…</>}` | Fills the named slot of that name ([Named slots](./stories-and-scenarios.md#named-slots)). A fragment is flattened into its nodes. Angular and Vue print a named slot (`ng-template`, `<template #name>`) before the default content, the order a component renders them in; React slots are attributes |
| `<Tabs.Root>`, `<Tabs.Trigger>` | A component with several parts is written one tag per part, `<Name.Part>` ([Compound components](#compound-components)) |
| `render={<Button variant="outline" />}` on a part | Another component renders the part ([Part composition](#part-composition)) |
| `name={({ field }) => <>{field.length} items</>}` | The content of a scoped slot (no component has one at present; the Select custom trigger is [S26](./compiler-limitations.md)) ([Scoped slots](#scoped-slots)) |
| `class="toolbar"` on a native element, with `styles` in `defineStory` | A container the story styles ([Story styles](#story-styles)) |
| JSX text | Trimmed like JSX text. Text next to inline elements keeps the spaces the author wrote. Entities: the common named ones (`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&nbsp;`, `&eacute;`, `&laquo;`, …) and numeric references to printable characters; any other entity is an error, and so is a numeric reference to a control character. Layout white space is defined in [playground-and-snippets.md](./playground-and-snippets.md#layout-of-printed-markup). A no-break space (`&nbsp;`, `&#160;` or the character) is text: it prints as `&nbsp;` in all three frameworks. Every other Unicode space (U+2000 to U+200A, `&ensp;`, `&emsp;`, `&thinsp;`, U+3000 and the like) is an error, as an entity, a numeric reference or a character, because Angular drops or merges it: write a space or `&nbsp;` |

## Args

A custom or theme story may declare args: the values the controls of its block change. `args` is an object of literals, `argValues` lists the values of a string arg, and `render` takes the args as one destructured parameter.

```tsx
export default defineStory({
  title: 'Character count',
  description: 'The hint counts the characters left while you type; Clear empties the field.',
  args: { maxLength: 80 },
  render: ({ maxLength }) => {
    const message = state('');
    const remaining = derived(maxLength - message.length);
    // …
  },
});
```

| Rule | Detail |
|---|---|
| Declaration | `args: { name: literal, … }` with a string, finite number or boolean literal each, which is the default. `argValues: { name: ['a', 'b'] }` lists the values of a string arg: it gets a select control, and its default is one of them. A list is a non-empty array of distinct string literals, for a declared string arg (`invalid-value`, `unknown-reference`) |
| Controls | From the literal: a boolean is a switch, a string a text field, a number a number field, a listed string a select. The arg is in `StoryMeta.args` with `group: 'props'` and an empty description. Initial args: [preview protocol](./preview-protocol.md#live-and-initial-args) |
| Parameter | Only `({ a, b })`, naming declared args. `(args) =>`, a renamed or defaulted name and a rest element are `unsupported-syntax`; a name that is not an arg is `unknown-reference` |
| Reading | A bare name as an attribute, prop or theme option value (`maxlength={maxLength}`), in a `derived` (`derived(maxLength - message.length)`), and as text (`{maxLength}`; a string or number arg, a boolean is `invalid-value`). A larger expression over an arg, in text, in a `when` condition or in an attribute (`maxlength={maxLength - 1}`), and an arg as a `when` condition, are `unsupported-syntax` with the hint to read the arg in a `derived`: the snippet fills a bare arg and prints no expression. `state` never starts from an arg (`invalid-state`), and a handler never reads one, directly or through a `derived` (`invalid-handler`) |
| Union values | A select arg may set a union prop or a theme option when every value of its list is a member there: the compiler checks the list as it checks a literal, and the author typing of the arg is that union (`StoryArgsOf`), so TypeScript gives the same answer. A text arg holds any text and never sets one (`invalid-value`) |
| `form(model, validators)` | `const signUp = form({ email: '', password: '', terms: false }, { email: [required(), email()], password: [required(), minLength(8)], terms: [required()] })`. The model is an object of string and boolean literals, one field each; the validators are an object of lists by field name, called by name with no function: `required()` (a text that is not empty, a boolean that is `true`), `email()`, `minLength(n)` and `maxLength(n)` (whole numbers from 0; on a string field only; each once for a field, a minimum not above the maximum). `required`, `email`, `minLength`, `maxLength`, `form` and `reset` come from `@cocokits/story-compiler/language`, and a declaration, an `each` item or an `each` index named like a name the file imports from it is `name-collision`. A field named `valid` or `invalid`, or like a member of every object, is `name-collision`. The markup, a `derived` and a handler read `signUp.valid`, `signUp.invalid` and, of a field, `signUp.email.value`, `.valid` and `.invalid` (anything else, a bare `signUp.email` and the form itself as a value included, is `invalid-value` or `unknown-reference`); `.length` reads the length of a string `value`. The empty text passes every validator but `required`, and `email()` accepts the addresses Signal Forms accepts, in the three frameworks. Every name the code declares for a form is reserved in all three frameworks, and two fields or forms whose names meet are `name-collision` at the field (`email` with `submitted` in `signUp`; `signUp` with `email` beside `sign` with `upEmail`). How Angular, React and Vue print a form: [compiler README](../../../tools/story-compiler/README.md) |
| `control={signUp.email}` | On a component with a model of the field's kind (a string field a value model, a boolean field a checked model) and a delivery contract ([Interaction portability](./interaction-portability.md#delivery-contracts)): the component follows the field and writes it, and the form validates it. Angular prints `[formField]="signUp.email"`. React prints the model as `bind` does (`value={signUpEmail}` with `onValueChange`, `checked` with `onCheckedChange`) and `invalid={!signUpEmailValid}`, `touched={signUpEmailTouched}`, `submitted={signUpSubmitted}`, `required` (when the field has `required()`) and an `onBlur` that sets the touch; Vue prints `v-model` and `:invalid`, `:touched`, `:submitted`, `required` and `@blur`. The component's own touch and submit would not follow a reset that the story makes with `reset(form)`, so the printed code gives them. An `onBlur` the story writes on the same component is printed after the touch, in one handler (neither framework prints the attribute twice). The form owns what the control would otherwise set, so `control` is `invalid-value` beside `value`, `checked`, the initial value (`defaultValue`, `defaultChecked`), `required`, `disabled`, `readOnly`, `name`, `invalid`, `touched`, `submitted`, the change handler of the model and a native `onInput` on the same component (Angular refuses the first group next to `[formField]`, NG8022, and the frameworks must agree), and `invalid-bind` beside `bind`. It is `invalid-value` on a component with no model, on a native element (a native text input uses `bind`) and for a field of the other kind, `event-attribute` ("out of domain") on a component with no contract, and `unknown-reference` for a field the form lacks |
| `reset(form)` | A statement of a handler: the form goes back to its initial values and forgets what its fields remember of the user (touched, submitted), so the errors hide. The Reset Button of a `form()` form has `type="button"` and `onClick={() => reset(signUp)}`: Signal Forms does not hear a native reset, so a `type="reset"` control inside a form that holds the controls of a `form()` is `invalid-handler` with this hint. `reset` of anything but a form is `invalid-handler` |
| `<form>` and `onSubmit={handler}` | Every story `<form>`, except a `method="dialog"` form in the Dialog Content, prevents the browser's submit, printed by the compiler in each framework (Angular `(submit)="$event.preventDefault()"`, React `onSubmit={(event) => event.preventDefault()}`, Vue `@submit.prevent`), so a story never navigates the preview. A plain form prints no `novalidate` and keeps the browser's constraint validation, which is the same in the three frameworks: an empty `required` field blocks the submit. A `<form>` that holds the controls of one `form()` is a `form()` form (the controls of two forms in one `<form>` are `invalid-value`): it turns the browser's checks off and, in the same three steps in every framework, prevents the submit, marks every field as submitted and runs the handler when the form is valid. `onSubmit={handler}` (a native event handler: no parameter) is accepted on a `form()` form, where it is the submission action, and on a plain `<form method="dialog">` inside a part that renders a `dialog` (the Dialog Content); on any other plain form it is `event-attribute` until a story needs it. A `<form method="dialog">` closes its dialog natively (no request, no navigation), so it prints no `preventDefault` and the handler is the event of the framework: Angular `(submit)="save()"`, React `onSubmit={save}`, Vue `@submit="save"`. A literal `method="dialog"` anywhere else (outside a dialog, where the submission does nothing) and on a `form()` form (which keeps its framework submit) is `invalid-value`, and so is `formmethod` or `formaction` on a control inside a `method="dialog"` form (it overrides the form). A form with no `onSubmit` prints no submission options, and the submit still marks the fields, so every error shows |
| Names | The rules of a declaration's name (State and handlers, Names) hold for an arg, and an arg and a declaration cannot share a name (`name-collision`), and `<name>Model` of a `form()` (the Angular signal of its values) and the names React and Vue declare for it (`<name><Field>`, `<name><Field>Touched`, `<name><Field>Valid`, `<name>Submitted`, `<name>Valid`, `reset<Name>` and the React setters) |

The author typing is `defineStory` with `args` and `argValues` (`StoryWithArgs` in `@cocokits/shared`): the `render` parameter has each listed arg as the union of its list and every other arg as the widened kind of its literal. A story without `args` keeps `render: () => …`. How the code shown and the snippet follow the controls: [playground-and-snippets.md](./playground-and-snippets.md#the-playground-snippet).

## State and handlers

A story that needs a value to change has a block body: `const` declarations, then one `return` of markup. Nothing else may appear in the block (no `if`, `let` or loop statement; markup repeats with `each`). The constructs are typed markers imported from `@cocokits/story-compiler/language` (the authoring entry of the compiler, which imports no other package, so no published package carries them); the compiler reads them and never runs them.

```tsx
// a disclosure Button that says whether the details are open
render: () => {
  const open = state(false);
  return (
    <Button
      aria-expanded={open}
      onClick={() => {
        toggle(open);
      }}
    >
      Shipping details
    </Button>
  );
},
```

| Construct | Rule |
|---|---|
| `state(literal)` | A string, number or boolean literal, nothing else: a state never starts from another value (`invalid-state`). Its kind is the literal's kind: `state('outline')` is a `string`, which a union cannot take |
| `state<CatalogType>(literal)` | The one type argument the language accepts: the name of a catalog type ([Catalog types](#catalog-types)) and a string literal. Any other type argument is `unsupported-syntax` |
| `derived(expr)` | An expression over states, args ([Args](#args)) and earlier derived values. Read-only: `set` and `toggle` refuse it |
| List | `const sizes = ['sm', 'md', 'lg']`: a non-empty array of string literals or of number literals, each once (an empty list, a repeat and a mixture of strings and numbers are `invalid-value`, any other item is `unsupported-syntax`). Only `each` reads it: a list used as a value is `unknown-reference`, and `set`, `toggle`, `bind` and an event attribute refuse it. It is printed as a `const` array (an Angular class field) |
| List state | `const toppings = state(['Cheese'])` or `state([])`: a list of distinct text items that changes, read with `add`, `remove`, `set`, `.length` and `each` ([List state](#list-state)) |
| Handler | `const name = () => stmt` or `() => { stmt; stmt; }`, with the statements `set(state, expr)`, `toggle(state)` (a boolean state), `reset(form)` and, on a list state, `add(list, value)`, `remove(list, value)` and `set(list, ['a'])` ([List state](#list-state)). A native event handler takes no parameter. A component event handler takes none or one: the event's value, named by the author, of the kind the model has (boolean for a checked model, string for a value model, list of text for a list model), and it can only set a state to it as it is, `set(draft, text)` or `set(chosen, list)`. A second parameter, or any member access on the parameter, is `invalid-handler`. A handler that reads a state after it set that state is `read-after-set`: React keeps the old value until the next render |
| Event attribute | `onX={name}`, or `onX={() => stmt}` with one statement (more need a named handler). Story files of this repo use the block form, `onClick={() => { toggle(open); }}`, because ESLint refuses the shorthand; the compiler reads both alike. The events and their hosts are in [Interaction portability](./interaction-portability.md). A component with a delivery contract also takes the `on<Event>` of the change event of its model, named after the semantic id of the event in its `ApiDoc` (`onValueChange` on the Input): `onValueChange={(text) => set(draft, text)}`, or the name of a handler that takes the value. It is printed as the event of the framework (Angular `(valueChangeDetails)="copy($event.value)"`, React `onValueChange={copy}`, Vue `@update:model-value="copy"`). Any other `on*` name on a component is `event-attribute`, and so is the change event of a model on a component inside a `form` or with a `form` attribute (out of domain; use `bind`, or `control` for a `form()`) |
| Expression | A literal; the name of a state, an arg or a derived value; `name.length` of a declared string name; `!a`; `&&`, `||`, `===`, `!==`, `<`, `<=`, `>`, `>=`, `+`, `-`; `a ? b : c`; parentheses. They are the operators of JavaScript with the same meaning, printed as the same expression in the three frameworks (Angular reads signals: `count() < 3`). `!`, `&&` and `||` take booleans; `===` and `!==` take two values of one kind and never two literals; `<`, `<=`, `>`, `>=`, `+` and `-` take numbers (`+` does not join text: write text beside the values); the test of `? :` is a boolean and its two branches have one kind. A mistaken kind is `invalid-value` at the operand. `*`, `/`, `%`, `==`, `??`, `?.`, calls, assignments and any operator in front of a value other than `!` (a negative number literal is a literal) stay `unsupported-syntax`, and so does markup inside an operator (`open && <p />`: write `when`). `===` and `!==` never take an arg, directly or through a `derived` (`invalid-value`): the code shown holds the arg's current value, and TypeScript refuses to compare values that cannot meet. A comparison of a state that has a catalog type with a text outside the type, with a choice of texts one of which is outside it, or with another catalog type that shares no value is `invalid-value` (TypeScript refuses it in the printed code); so is a comparison of a catalog-typed state with a choice of texts that comes from a `derived`, whatever its values (the compiler cannot match them to the type: write the choice in the comparison), and so is a choice of text (`a ? 'x' : 'y'`) that sets a union prop, a theme option or a catalog-typed state, because the compiler cannot match its values to the type |
| Expression attribute | `name={expr}` on a native attribute, a prop or a theme option, checked against the kind of the attribute (boolean, string or number) like a literal. A union prop or a theme option takes a literal, a `derived` literal or a state typed by its catalog type ([Catalog types](#catalog-types)), never a bare `state('…')`; a boolean option takes an expression only when every value it can hold is a member of its values: the initial value of the state, every value a `set` gives it and every literal a `derived` returns (otherwise `invalid-value`). A state bound to an input holds any text, so it never sets one, directly, through a derived value or through a `set` (`invalid-value`). An expression cannot set the `value` or `checked` of an `input`, the `size` of an `input` or a `select` (React drops a size below 1, and on an `input` Vue's DOM property refuses 0, so the frameworks would differ), or a URL attribute or prop (`href`, `src`, `action`, `formaction`): those take literals. An id reference (`aria-controls`, `aria-describedby`, `aria-labelledby`, `aria-owns`, `aria-flowto`, `aria-activedescendant`, `aria-details`, `aria-errormessage`, `for`) takes a string, and a boolean on an attribute of kind `any` that is not `aria-*` (an SVG length) is `invalid-value`. Boolean attributes such as `hidden` and `disabled` take boolean expressions |
| Text | `{expr}` in markup, of kind string or number. A boolean, a boolean literal (`{true}`) included, is `invalid-value`, because React renders nothing for it |
| `when(condition, then, otherwise?)` | In markup as a child. `condition` is a boolean expression (a boolean state or derived value, `true`/`false`, or an operator that gives a boolean, see Expression); a condition of another kind (a string or a number) is `invalid-value`. `then` and `otherwise` are markup, text or a fragment; an empty fragment, `<></>`, shows nothing. A `when` may sit in a branch of another. It is `slot-content-mismatch` when it is written directly as content of a component that has named slots (in a named slot with an Angular selector, or as the children): Angular projects a branch by its single root element, so it could place the content differently from React and Vue. Put the `when` inside an element |
| `each(list, (item, index?) => content)` | In markup as a child, to repeat markup for each item of a constant list: `each(sizes, (size) => <Button size={size}>{size}</Button>)`. The rules are in [each](#each) below |
| `bind={state}` | On a native `input` whose `type` is `text`, `email`, `search`, `tel`, `url`, `password` or absent, with a string state. The value follows the state, and typing writes it; it is how an `input` takes a state as its value, because an expression cannot set `value` or `checked`. It is `invalid-bind` on anything else, next to a `value` (literal or expression), when the state is bound twice, and on a native input inside a `form` or with a `form` attribute: a native reset changes the field but not the state (the message says to bind a CocoKits Input, which restores its text and reports it). On a component whose `ApiDoc` has a model and that has a delivery contract (the Input, Textarea, Checkbox, Switch, RadioGroup and Select; [Interaction portability](./interaction-portability.md#delivery-contracts)), `bind={state}` follows the model: a string state a value model, a boolean state a checked model. Printed as the two-way binding of the framework: Angular `[(value)]="name"`, React `value={name} onValueChange={setName}` (the setter itself, as Base UI and Radix show; a bind with a report, or one that turns the `null` of an empty choice into the empty text, keeps an arrow function), Vue `v-model="name"`. It is `invalid-bind` next to the model's initial value (`defaultValue`), the model prop or its change handler (`onValueChange`), next to an `onInput` on the same component (Angular runs the component's event first, Vue and React the author's handler first), for a state of the wrong kind (a text state on a list model, a list state on a text model), a derived value, an arg or a catalog-typed state, and on a Radio, which takes no `bind` (bind its RadioGroup). A component `bind` inside a `form` or with a `form` attribute is allowed, also next to a native reset control: the Input, Textarea, Checkbox, Switch and RadioGroup restore their mount value and emit the change, so the bound state follows (the Events panel shows it; its reason is `form-reset` in Angular and React, and empty in Vue, whose `update:*` event carries the value only). A RadioGroup binds the text of the checked Radio ([Radio group](#radio-group)); a Select binds a text, or a list under a literal `multiple` ([List models](#list-models)). On a component with a model and no contract it is `event-attribute` ("out of domain"), and on a component with no model it is `invalid-bind` |
| Controlled checked model `checked={all}` | On a Checkbox or Switch, for select all. `all` is the name of a `derived` that is `&&` (all of them) or `||` (any of them) of two or more boolean states, each once. The same element has an `onCheckedChange` handler that sets every one of those states to its parameter (`set(news, checked)`), and no other value to any of them. It is `invalid-value`, each with a hint, for a bare state (use `bind`), a literal (use `defaultChecked`), any other expression or derived value (a `!a`, a mix of the two operators, a derived value over another one), no such handler, a Checkbox or Switch inside a `form` (the reset reports of its peers would rewrite a controlled model), a value model (the Input and the Textarea) and a Radio, and beside `bind` or `defaultChecked`. Printed as the live value and the change event: Angular `[checked]="all()" (checkedChangeDetails)="setAll($event.value)"`, React `checked={all} onCheckedChange={setAll}`, Vue `:model-value="all" @update:model-value="setAll"`, with no `v-model`. The mixed state is the `indeterminate` prop of the Checkbox, set from a `derived` |
| Names | camelCase letters and digits, not a reserved word, unique in the story. The item and the index of an `each` are names too, in the scope of its callback: they may not repeat a name of the story, of an arg or of an outer `each` (sibling `each` blocks may reuse one). A name the printed code uses is `name-collision`: `set<Name>` of a state, `<name>Field` of a bound state (the Angular template reference of its input), `props`, `key`, `cdr`, `inject`, `value`, `signal`, `computed`, `input`, `ref`, `useState`, `undefined`, `NaN`, `Infinity`, `constructor`, `prototype`, every `Object.prototype` member and any `ng` followed by an upper-case letter |

Which element takes which event, what is out of the language, and how two handlers of one interaction must relate: [Interaction portability](./interaction-portability.md). An event on a host that takes none, an event the element kind refuses, and an element out of the domain are `event-attribute`; any other `on*` is too, except `onVnode*` (`name-collision`). `class` and `style` stay `styling-attribute`, and a `stories.config.ts` `sample` stays literals only.

How each construct is printed, `'use client'` included, is in the [compiler README](../../../tools/story-compiler/README.md).

### `each`

`list` is the name of a list of the block. The callback is an arrow function with an expression body and one plain parameter, the item, or two, the item and the index (a number from 0); its content is markup, text or a fragment, and an empty one is `unsupported-syntax`.

- **Where the item and the index are read.** They are values of the markup only: text (`{name}`) and the expressions of an attribute, a prop or a `when` condition (`aria-label={name}`, `when(index > 0, …)`). A handler never reads them (`invalid-handler`: a handler is declared once, for every repeat). The item is the key of its repeat.
- **Ids.** Every copy of the content prints the same literal, so a literal `id` repeats on every copy (and a `for` names the first one): build an id from the item (`id={name}`).
- **Attributes.** A string item sets a native attribute only where any text is a valid value: `id`, `title`, `name`, `aria-label` and the like. On an attribute with a fixed set of values (`button` `type`, `aria-live`, `aria-current`, …) it is `invalid-value`, because React and Vue type the attribute as a union and the list is `string[]`. A number item or index sets a number attribute and the numeric `aria-*` attributes (`aria-level`, `aria-posinset`, `aria-valuenow`, …); on any other `aria-*` (`aria-label`, `aria-live`) it is `invalid-value` too. The item of a text list is text: it cannot set a union prop or a string theme option (`invalid-value`; write one element for each value).
- **A constant list.** Each item is written once, so no update adds, removes or moves a repeat, and the rules of [Interaction portability](./interaction-portability.md) read the `when` around or inside an `each`, not the `each`.
- **Nesting.** An `each` may hold a `when`, sit in a `when`, and hold another `each` with other names. It is `slot-content-mismatch` where a `when` is: written directly as content of a component that has named slots.
- **Printed as** `@for (item of list; track item)` (the index is `let index = $index`), `list.map((item, index) => …)` with `key={item}` on the element or a `<Fragment key={item}>` when the content is not one element, and `v-for="item in list" :key="item"` on the element or a `<template>`.


### Radio group

A RadioGroup holds the value of the group, so the group is what a story binds; a Radio inside it takes no `bind` and no change handler (`invalid-bind` and `invalid-handler`, both naming the group), and keeps `defaultChecked` and `value`.

- `bind={plan}` with a string state: the group follows the state and a user check writes it. Nothing checked reads as the empty text. `onValueChange={(value) => set(plan, value)}` (or a named handler) takes the value of the change. Printed as the two-way binding of each framework: Angular `[(value)]="plan"`, React `value={plan}` with `onValueChange`, Vue `v-model="plan"`.
- `control={order.plan}` with a string field of a `form()`: the group follows the field and writes it, and `required()` blocks the submit until a Radio is checked. The printed code gives the facts the component has: the value, `required` and the touch when the focus leaves the group. The RadioGroup has no `invalid`, `touched` or `submitted`, so the story shows its own error text (`when(order.plan.invalid, …)`).
- `defaultValue="free"` is the initial check of an unbound group. A Radio takes a `value` that is a text or an item of an `each`, and no `onCheckedChange`.

## Catalog types

**The rule: the compiler and TypeScript agree.** Every story the compiler accepts type-checks in the author typings (`jsx.d.ts`) and in all three printed outputs (`ngc` with `strictTemplates`, `tsc` and `vue-tsc`). Every value the author typings reject is also a compiler error, with a precise location and a fix hint: a did-you-mean, or the name of the catalog type to write. The compiler may refuse more than TypeScript, never less. [`tools/story-compiler/tests/catalog-agreement.test.ts`](../../../tools/story-compiler/tests/catalog-agreement.test.ts) runs one corpus of stories through both and fails on any disagreement.

Union values come from the catalog type, never from a bare widened string. A state that sets a union prop or a theme option names the catalog type of its values: `const look = state<ButtonVariant>('outline')`, `const kind = state<FieldType>('email')`. The catalog is generated, never written by hand: from the `ThemeConfig` of the themes (one type per theme option whose values are strings) and from the `ApiDoc` of the components (one type per union prop). Each type is global in the generated `jsx.d.ts` with TSDoc, so a story imports nothing for it.

| Name | Values | Where a story can use it |
|---|---|---|
| `<Component><Option>`: `ButtonVariant` | The values every theme that lists the component has (the intersection). Left out when a theme lacks the option or no value is common | Any story |
| `<Theme><Component><Option>`: `CocokitsButtonVariant` | The values of that theme | A story in the folder of that theme |
| `<Component><Prop>`: `FieldType` | The values of a union prop of the `ApiDoc` | Any story whose themes all list the component |

What the compiler checks, whether or not a prop reads the state:

- **Every assignment, by the declared type of what is assigned.** The initial value and each `set`, in a named or an inline handler, must be a value of the type. A `set` from another state needs that state to have a catalog type inside the target's; a state of any text (`state('light')`, or one an input binds) is refused, because TypeScript refuses a `string` where a union is declared. A `derived` has the type of the state it reads.
- **A bare state never reaches a union.** A `state` without a catalog type that reaches a union prop or a string theme option, directly or through a `derived`, is `invalid-state` at its declaration, naming the type to write (`declare it as state<ButtonVariant>("outline")`, or the theme name in a theme folder). A literal and a `derived` literal need nothing more. A state that an input binds can hold any text, so it cannot have a catalog type and cannot set a union (`invalid-value`).
- **Domain.** A catalog type must lie inside the values of the place it sets, as the author sees the type and as the printed code types it (a theme package exports the whole option, which can hold more than a shared type). Otherwise `invalid-value`, naming the catalog type of that place.
- **Names.** A wrong initial value or `set` is `invalid-value`: it lists the allowed values and, when one is near, suggests it. A name that is not in the catalog, the catalog of another theme, or `bind` on a catalog-typed state (the user could type any text) is `invalid-state` or `invalid-bind`. Two generated catalog names that are equal, or equal to a type the typings declare (`JSX`, `<Component>Props`) or to an ambient type of the TypeScript library the author typings use (`Input.event` would be `InputEvent`, the DOM type; the names are read from that library, not listed), are `name-collision` at the theme data or `ApiDoc` file that defines the type; rename the option, the prop or the component.

In the editor, `state` keeps an explicit union, `set` cannot widen it (`NoInfer`), and a wrong literal is an error in the story source. How each framework prints a catalog state, with its import, is in the [compiler README](../../../tools/story-compiler/README.md).

Values are checked too, so a story cannot carry what the theme or the page owns:

- `data-*` attributes are output only ([architecture §3](../../architecture.md#3-anatomy-and-the-styling-contract)), so a story cannot set one.
- `fill` and `stroke` are `currentColor` or `none`: stories carry no colours.
- `href`, `src`, `action` and `formaction` cannot be a `javascript:`, `data:` or `vbscript:` URL. The rule follows the name, whether it is a native attribute, a prop, a theme option or a `sample` key, and it covers the values a generated story would print (a union member, a default, an option value).
- An attribute value has no carriage return: Angular reads it as a line feed, so the frameworks would differ.
- A prop or option name is letters and digits and not a JavaScript reserved word (`default`, `class`, `new`, …), because the printed code uses it as a variable. A string, number or other prop that is never a boolean or a union may have a reserved word (the `for` of a Label) or an `aria-*` / `data-*` name (the `aria-describedby` of an Input) as its name: it is printed only as an attribute or a binding, and gets no control.
- A void element (`input`, `img`, `br`) and a component without a default slot take no content. A slot marked `@cckSemantic none` is not a default slot, so a Badge takes no content. Numbers are finite.
- `aria-*` names are lower-case letters after `aria-`.

## Story styles

A story may style the native container elements it writes, so a layout such as a clipped box is written once and shows in the copied code. `defineStory({ styles })` takes a string or a template literal with no substitution, and `class` on a native element names the classes it defines.

```tsx
export default defineStory({
  title: 'In a clipped container',
  description: 'The content is portaled, so overflow and transform of an ancestor do not clip it.',
  height: 280,
  styles: `
    .clip-box { overflow: hidden; transform: translateZ(0); width: 240px; height: 72px; padding: 12px; border: 1px dashed currentColor; }
  `,
  render: () => <div class="clip-box">…</div>,
});
```

| Rule | Detail |
|---|---|
| Rules | Only rules of one class selector (`.name { … }`): no at-rule, combinator, pseudo-class, nesting or `!important` |
| Class names | Kebab case, not starting with `cck-` (theme classes belong to the theme), each defined once, each used by an element |
| Properties | Layout only: `display`, `flex-direction`, `flex-wrap`, `align-items`, `justify-content`, `gap`, `overflow`, `overflow-x`, `overflow-y`, `transform` (`translate*`, `scale*`, `rotate*`), `position: relative`, `width`, `height`, `min-*`, `max-*`, `padding*`, `margin*`, `border` and `border-*-style` or `-width` with `currentColor` as the only colour. `padding`, `margin` and `border` take the top and bottom sides and the logical axes, `-inline` and `-block`, each with `-start` and `-end` (`padding-inline-start: 8px`, `margin-block: 4px 0`, `border-inline-end-width: 1px`), which follow the writing direction; the physical `-left` and `-right` sides are `invalid-style` and the message names the logical property to write (`margin-inline-start`). Lengths are in `px`, `rem`, `em` or `%`. A colour other than `currentColor`, a font, `var()` and any other property are `invalid-style`: the theme owns them |
| `class` | A literal string of class names the story defines, on a native element only. On a component, a part or a `sample` key it stays `styling-attribute`, reported before any other code on that node; `style` and `className` stay `styling-attribute` everywhere. A class the story does not define is `unknown-attribute` |
| Printing | Angular: `styles` in the `@Component` (emulated encapsulation) and `class`. React: a second file `<id>.css` with the rules, `import './<id>.css';` in the module and `className`; the file is the second entry of `StoryMeta.files`, so the files list shows it. Vue: a `<style scoped>` block and `class`. Plain CSS, no CSS Modules |

React story CSS is global. A reader who copies a class into an app renames it, because it keeps its story name.

## Compound components

A component whose Angular `ApiDoc` names more than one part (counted by distinct semantic id; a Button's two hosts are one part) is written with one tag per part, `<Name.Part>`: `Name` is the PascalCase of the component and `Part` the PascalCase of the part (`tabs.root` is `Tabs.Root`, `select.optionGroup` is `Select.OptionGroup`). A single-part component keeps `<Name>`.

```tsx
<Tabs.Root defaultValue="account">
  <Tabs.List aria-label="Account settings">
    <Tabs.Trigger value="account">Account</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Panel value="account">Change your name and email.</Tabs.Panel>
</Tabs.Root>
```

- Each part has its own usage model, built from the framework's `ApiDoc` by semantic id: its props, theme options (`partNames`), models, slots and host. The members of a part other than the root carry the part in their semantic id (`tabs.trigger.value`). `default<Model>` and `bind` work on any part that has a model.
- A part sits inside a root of its own component (`part-placement` otherwise). The bare component name (`<Tabs>`) is `unknown-component` and names the parts.
- React prints `Tabs.Trigger` and imports the namespace; Vue prints `TabsTrigger` and imports each part; Angular imports `Cck<Name>Imports`.
- **What Angular renders itself.** A part that an Angular directive renders internally (the `renders` of its `ApiDoc`: the Tabs list) prints no element in Angular. Its attributes go to the directive that renders it, which must have an input of that name (`aria-label` on `cckTabs`), and its children become content of that directive at its default slot. Any other native attribute, `as` or `render` on such a part is `unsupported-host`. The part must be a direct child of the one that renders it (or of another part that one renders), the first child with no text, element or part before it (`part-placement`: put a heading outside `Tabs.Root`), once, and the renderer needs it (`Tabs.Root needs exactly one Tabs.List`).
- **Templates and roots with no element.** A part declared inside an `ng-template` (an overlay content part, `templateSelector`) prints that wrapper in Angular: `<ng-template cckPopoverPortal><div cckPopoverContent>…</div></ng-template>`. A root that renders no element prints `<ng-container cckPopover>`; a native attribute or `as` on it is `unsupported-host`.
- **Sections (Angular).** Where an Angular directive is a section (`section`: `CckTab` also stands for `Tabs.Trigger`, `CckAccordionItem` for `Accordion.Trigger`), the story still writes the parts as siblings, as in React and Vue, and the printer joins the part the section also stands for (the trigger) with the part it stands on (the panel, the item) into one element: the trigger's props become inputs of the element, its content the input the section names when it is one string (`label="Account"` for a tab, `label="Shipping"` for an Accordion item; `[label]="name()"` for an expression) and otherwise the `ng-template` of the section's slot first inside the element (`<ng-template cckTabLabel>…</ng-template>`, `<ng-template cckAccordionLabel>…</ng-template>`). The join is keyed by `value`, the part's own or its nearest ancestor part's. A trigger inside its holder (an Accordion item, in its header) joins by ancestry, and the item takes one. A trigger in another container (the Tabs list) joins with the panel in the same place of the sequence: both one by one, with the same literal `value` in the same order, or both one `each` over one list with one item name (the index name must agree only when both declare one; the printed `@for` declares it when either does). Panels may sit in native elements at any depth below the root, never in another component. The list holds triggers only. `compound-mismatch`: the counts differ, a trigger has no panel (Angular has no trigger without a panel), the `value`s of pair i differ (the panels are written in the order of the triggers), one side is written one by one and the other with `each`, the lists or item names differ, or a `when` around a trigger or a panel breaks the rule of the next bullet. `unsupported-host`: a native attribute or `as` on a trigger that no input of the section takes (`id`, `title`, other `aria-*`). `event-attribute`: an element event on a trigger or on a part Angular renders, which has no element to take it. The generated playground goes through the same join.
- **One tab or item in a `when`.** A tab whose trigger and panel each sit in a `when` on the same state or derived name (`{when(billing, <Tabs.Trigger value="billing">…</Tabs.Trigger>)}` and the same around its panel) can be shown and hidden. Each `when` wraps only that part, tests one name and has no otherwise branch, and no `each` repeats the part. React and Vue print the story as written; Angular prints one `@if` around the joined tab. Two tabs may have their own conditions. Any other shape is `compound-mismatch` and names the rule (a `when` around the whole root is still fine). A trigger inside its holder (the header of an Accordion item) cannot be absent alone. An Accordion item may sit in a `when` as it is. In Angular the Tabs keep the selected tab when a tab before it comes or goes, as Material's `MatTabGroup` does, and report no change for the shift, so a Tabs root with a tab in a `when` takes no `bind` and no change handler, and its `defaultValue` names a tab that no tab in a `when` precedes (`compound-mismatch`, with that reason).
- **Accordion (Angular).** The Angular Accordion is a section (`@cckSection trigger label label`), so the join above applies and the item takes the trigger from its header. The item also renders the header and the content, so the printer adds these rules; React and Vue print the story as written.
  1. `Accordion.Header` and `Accordion.Content` print no element: the item renders them, and the children of the content become the content of the item. `as="hN"` on the header prints `headingLevel="N"` on the item (`h1` to `h6`; another element is `unsupported-host`).
  2. On the root, `type="multiple"` prints `multi`, and `type="single"` prints nothing. A `type` arg of the playground prints `[multi]="type() === 'multiple'"`.
  3. `collapsible` and the `value` of an item print nothing: Angular items always close, and have no key.
  4. The root's `defaultValue` (an array of string literals) prints `[expanded]="true"` on each item whose literal `value` it names. An item with a `value` that is not a string literal next to a `defaultValue` is `compound-mismatch`.
  5. Refused in Angular as `unsupported-host`, with a message that names the member and says why: root `disabled` (Angular disables each item), `orientation` (always vertical), `dir` (the direction comes from `Directionality`), `unmountOnHide` (the content is always rendered), content `forceMount`, and any other attribute on the header, the trigger or the content (no element of their own). `bind` is `invalid-bind` and `onValueChange` is `event-attribute`: Angular has no root value, and in React and Vue the list model of the root cannot follow a state either.
  6. A generated story or control for a member Angular refuses is an error that names the member: add the member to `hideControls` and the id of its story to `skip` in the config of the Accordion, which hides it in the three frameworks.
- **Tooltip (Angular).** The Angular Tooltip is one attribute on the trigger (Material's form), so the printer folds a `<Tooltip.Root>` that holds one `<Tooltip.Trigger>` and one `<Tooltip.Content>` of literal text into the trigger's element: `cckTooltip="<text>"`, the root's `delay` and `disabled` as `cckTooltipShowDelay` and `cckTooltipDisabled`, the content's `side` and `align` as `cckTooltipSide` and `cckTooltipAlign`. A `render` on the trigger keeps both directives on the one element (`<button cckButton cckTooltip="Delete" cckTooltipSide="bottom">`). A root with any other attribute (`disableClose`, a handler), a content with an attribute beyond `side` and `align`, or a content of markup, an expression or an arg keeps the compound form (`<ng-container cckTooltip>` with the trigger, the portal template and the content). React and Vue print the story as written.
  1. `defaultOpen` starts the tooltip open. The Angular Tooltip has no open state to bind, so the class gets a template reference (`#tooltip="cckTooltip"`) and `afterNextRender(() => this.tooltip().show(0))`; the playground's `defaultOpen` arg runs `show(0)` or `hide(0)` in an `afterRenderEffect` when it changes. The inline code a reader copies leaves the arg's call out, as it leaves out the other values the component has anyway. A story opens one tooltip this way.
  2. `open`, `bind={open}` and `onOpenChange` have no Angular form: the root has no open model and no output, so `open` is `unsupported-host` and a scenario cannot `expectEvent('openChange')`. A scenario checks the tooltip content (`expectAttr(role('tooltip'), 'data-state', 'open')`, `expectAbsent`), which every framework shows.
  3. The Tooltip `Provider` (React and Vue) and the React and Vue positioning props of the content (`sideOffset`, `alignOffset`, `avoidCollisions`, `collisionPadding`, `sticky`, `hideWhenDetached`) have no Angular part or input: the compiler does not treat a part flagged `frameworkOnly` as a missing convention, and a story that writes one fails in Angular ([limitation S24](./compiler-limitations.md)).
- **Tabs (Angular).** Angular selects a tab by its index and has no `value`. The story keeps the value of the tab (React and Vue select by it), and the printer finds the index of the tab in the order of the story (a trigger in an `each` over a list counts as the items of that list). React prints `Tabs.Content` and Vue `TabsContent` for the story part `Tabs.Panel`; Angular prints no element for `Tabs.Indicator`, `Tabs.List`, `TabNav.List` or `TabNav.Indicator`, which the Tabs and the Tab nav render.
  1. `defaultValue="b"` prints `[selectedIndex]="1"`. The `value` of a trigger and of a panel print nothing.
  2. `bind={state}` prints `[(selectedIndex)]="state"`, and the state holds the index of the tab in Angular: its start value and every `set(state, 'b')` are printed as the index (`signal<number | null>(0)`, `this.tab.set(1)`). So the start value and every `set` must be the literal `value` of a tab (`invalid-bind`), and a story cannot read the state (`{tab}`, a `derived`, a `when`): show the selected tab with its panel (`invalid-bind`).
  3. `onValueChange` is the output `selectedTabChange`, which reports the index of the tab the user chose. The handler cannot read the value (`invalid-handler`), and the Events panel shows the index in Angular.
  4. `forceMount` on every panel prints `preserveContent` on the Tabs; on some panels only, or as anything but `true`, it is `compound-mismatch`. Vue prints `force-mount` on each panel.
  5. `tabPanel="id"` on the Tab nav prints `[tabPanel]="idPanel"` and the panel with that `id` prints `#idPanel="cckTabNavPanel"`. The panel may stand anywhere in the story, not only inside the root; a `tabPanel` that names no `<TabNav.Panel>` is `compound-mismatch`. `hasActiveLink` prints nothing: the Angular nav tells its panel.
  6. `dir` and `loop` on the Tabs are refused in Angular (it reads `Directionality` and always wraps), and so is `unmountOnHide`.
- Generated stories and controls of the members of a part: [Stories and scenarios](./stories-and-scenarios.md#generated-stories).

## The `open` model and part events

- **Other models.** Any model of a root part prints from the `ApiDoc` like `value` and `checked`, `open` of an overlay included: `defaultOpen` starts it open (Angular `[open]="true"`, React `defaultOpen`, Vue `open`), `bind={open}` follows a boolean state (Angular `[(open)]="open"`, React `open={open} onOpenChange={setOpen}`, Vue `v-model:open="open"`) and `onOpenChange={…}` handles the change. `bind` and the handler need the component's delivery contract; `defaultOpen` and the report to the Events panel need none. The Angular Tooltip has no `open` model: see [Tooltip (Angular)](#compound-components).
- **The change event of `open`.** `onOpenChange={…}` prints as the change event of each framework: Angular `(openChange)="…($event)"`, the model output of `open`, which gives the value itself; React `onOpenChange={…}`; Vue `@update:open="…"`, which gives the value only. The Select and Tabs `value` is the same in Vue (`@update:model-value`). Only React (and Angular's `opened` and `closed`, which the story language does not write) tell why the overlay changed, so the Events panel row of an overlay in Angular and Vue has no reason.
- **`refuseWhile={state}`.** On the root of a Dialog, Popover, Tooltip or Select: while the boolean state or derived value is true, Escape and a press outside (the backdrop of a Dialog) do not close it. The attribute is the language's, not a prop of the component; it is named after what it does ("refuse while …") because each framework refuses in its own way and the compiler never shapes the API ([architecture §10](../../architecture.md#10-simplicity-and-reuse)). It takes the name of a boolean `state` or `derived` (a literal, an arg or another expression is `invalid-value`), only on an overlay root with an entry in `REFUSALS` (`interaction/contracts.ts`; `unknown-attribute` elsewhere, a part included), and its content part must be inside the root (`invalid-value`). Printed as Angular `[disableClose]="dirty()"` on the root, React `onEscapeKeyDown` and `onPointerDownOutside` on the Content with `(event) => { if (dirty) event.preventDefault(); }`, Vue `@escape-key-down` and `@pointer-down-outside` on the Content with the same handler. The Popover also refuses a focus that leaves it (React `onFocusOutside`, Vue `@focus-outside`), as `disableClose` does. A Close part, the trigger and a parent write still close the overlay; a Tooltip still hides when the pointer leaves or the trigger loses focus; a single Select still closes on a choice; no Select refuses a focus-out. The Tooltip takes `refuseWhile` without `bind` or `onOpenChange`, which it has no contract for.
- **Part events.** An event of a part that is not a model change (`activate` of a Menu item) is the attribute `on<Event>` on that part: `<Menu.Item onActivate={() => { set(choice, 'copy'); }}>Copy</Menu.Item>`. It is printed as the event of the framework (Angular `(activate)="…"`, React `onActivate={…}`, Vue `@activate="…"`). The handler takes no parameter, or the event's value when the event gives a string or a boolean (`onPick={(text) => set(choice, text)}`, with a state of that kind). It needs the component's contract (the row `item.activate`), and a part event named like a native DOM event (`select`, `toggle`) is `name-collision` at the `ApiDoc`, because React would read it as that event. A part event is not reported to the Events panel.
- **Overlay content** is a mounting condition for the portability check ([Interaction portability](./interaction-portability.md)): a handler of the content that the closing of the overlay may replace is refused.

## Part composition

A part with a polymorphism member (React `render`, Vue `asChild`, an Angular attribute selector) can be rendered by another component: `<Popover.Trigger render={<Button variant="outline" />}>Share</Popover.Trigger>`. The value is one component element with no children and only literal attributes, checked against the usage model of its own component; the content is the children of the part. React prints `render={<Button variant="outline" />}`, Vue `<PopoverTrigger as-child><Button variant="outline">Share</Button></PopoverTrigger>` and Angular one element with both directives, `<button cckButton cckPopoverTrigger variant="outline">Share</button>`; when the part's selector names an element, that element must be the rendered component's (`unsupported-host` otherwise). `render` with `as` on one part, on a native element or on a part without the member is an error (`unsupported-host`, `unknown-attribute`).

## Scoped slots

A slot that gives its content values (an `ApiDoc` slot with a `scope`) is written as an arrow function with one destructured parameter that names fields of the slot's scope: `name={({ field }) => <>{field.length} items</>}`. Inside, a field is read as text (a string or a number), `field.length` (a list or a string), in a `when` condition, and `each(field, (item) => …)` repeats markup over a list field; a list is never read as text. The content has no handler, `bind`, `control`, link or component with a model (`slot-content-mismatch`). Angular prints `<ng-template cckName let-field="field">…</ng-template>`, React the function, Vue `<template #name="{ field }">…</template>`. The typings give the slot prop `(scope: { readonly field: readonly string[] }) => JSX.Element`. A named slot whose Angular selector is an `ng-template` prints its content inside that template in Angular even without a scope, and takes markup like any named slot elsewhere.

## List state

`state([…])` is a list of distinct text items that changes: `const toppings = state(['Cheese'])`, or `state([])`, an empty list of text. A number list, mixed items and a repeated item are `invalid-value`.

| Construct | Rule |
|---|---|
| `add(toppings, value)` | Appends the text when it is not already there (nothing happens otherwise). `value` is a literal, a string state or the text parameter of a handler |
| `remove(toppings, value)` | Takes the text out |
| `set(toppings, ['a', 'b'])` | Replaces the list with a literal (`[]` empties it). In the change handler of a list model, `set(toppings, list)` takes the parameter as it is |
| `toppings.length` | A number: in text, in a `derived` and in a `when` condition |
| `each(toppings, (item) => …)` | Repeats over the current list, keyed by the item. The content is read-only, as scoped slot content is: a handler, `bind`, `control` or a compound part inside it is `slot-content-mismatch`, because a repeat can disappear under its own handler (rule R) and the Angular section join needs constant lists |

There is no `includes`, no read of an index and no list field in `form()`. A list state is the `bind` of a component with a list model and a delivery contract (a `multiple` Select) and the parameter target of its change handler. Every change makes a new array, so it is printed as Angular `signal<readonly string[]>([…])` with `update`, React `useState<readonly string[]>([…])` with the setter's updater, and Vue `ref<readonly string[]>([…])` replaced on each change. Angular templates have no arrow functions, so a list change written inline in a template is printed as a method of the class.

## List models

A model whose `ApiDoc` type is `string[]` or `string | string[]` is a list model. The Select is the one: a Select with a literal `multiple` follows a list, and one without it a single text, so `multiple` decides the kind of its model.

- `defaultValue` takes a non-empty array literal of distinct text literals: Angular `[value]="['Cake', 'Pizza']"`, React `defaultValue={['Cake', 'Pizza']}`, Vue `:default-value="['Cake', 'Pizza']"`.
- `bind={dishes}` takes a list state ([List state](#list-state)) and `onValueChange={(chosen) => set(dishes, chosen)}` its change. A Select without `multiple` takes a string state (`bind={dish}`, `onValueChange={(value) => set(dish, value)}`), where nothing chosen (a clearing item, a form reset) reads as the empty text: the printed code turns the `null` of the component into it.
- A `multiple` that is an expression beside `bind`, the handler or `control` is `invalid-value`, because the kind of the model must be known. `control` on a `multiple` Select is `invalid-value` too: `form()` fields stay text and boolean. A single Select takes `control={order.dish}` with a string field, and prints the facts the component has (`invalid` and `required`; the React and Vue Select has no `touched` or `submitted`).
- Angular follows the order of the options in the list of a `multiple` Select; React and Vue follow the order of the choices ([limitation S28](./compiler-limitations.md)).
- The playground has a `defaultValue` control: a select of the values of the sample's items and "none", and under `multiple` the chosen value is a list of one item.

A generic component is read with the default of its type parameter (`T = string`): the extractors write it in the member types, so stories and controls treat the Select as string-valued; function props of a generic (`itemToString`) and `items` are of kind `other`.
