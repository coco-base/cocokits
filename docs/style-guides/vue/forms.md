# Forms: native participation through `cdk/form-control`

Shared rules: [cdk-modules](../framework-agnostic/cdk-modules.md#form-participation). Contract: [architecture](../../architecture.md#6-props-events-and-forms-contract).

- A component whose control is not a native `input` or `textarea` renders the hidden input always, so the Root is multi-root and sets `inheritAttrs: false`. It is hidden with `visuallyHiddenStyle` from `@cocokits/utils`.
- In a custom control (one with a hidden input), the visible part activates the input with `inputRef.value?.click()`; state changes in the input's `@change` handler. The input's `@click.stop` keeps ancestors at one click; its `@focus` forwards to the visible part.
- A composable in `@cocokits/vue-core` wraps the cdk form-control module's form-tracking and input-syncing responsibilities (this guide fixes no API names): it keeps the input equal to the model (also after a parent rejects a change), follows the owning form (the `form` attribute, DOM moves), reset and disabled fieldsets, and exposes the initial value restored on reset.
- **Native text control** (`Input`, `Textarea`): there is no hidden input, and the Root is the native element (single root, attrs bound on it with `inheritAttrs: false`). Bind the model with `v-model`; after an emitted change the parent did not accept, write the model back to the DOM. `useFormParticipation` from `@cocokits/vue-core` reports reset, submit and fieldset, and writes the model value to the element.
- **Custom control with a `button` trigger** (the Select): the button is the `elementRef` of `useFormParticipation`. Its hidden inputs are `type="text"`, not `hidden` (a hidden input is barred from constraint validation), render for a `name` or `required`, and are made again after a form reset (the browser clears them); an `invalid` event on them returns focus to the trigger and is never canceled (a canceled `invalid` lets the submit go on).
- **Native choice control** (`Checkbox`, `Switch`, `Radio`): the native `input type="checkbox"` or `"radio"` is inside the component's template, so there is no hidden input and the Root is a `Primitive` that holds the label and the input. `inheritAttrs: false` sends `class`, `style` and `hidden` to the Root and every other attribute and listener to the input; the input's `type`, `role` and `aria-hidden` of the decorative parts come from the machine. Bind the checked state with `v-model` (a boolean); `useFormParticipation` in checked mode (`getChecked`, and `onUncheckedByGroup` for the Radio) writes `checked` back to the input after a change the parent did not accept. A group of Radios takes one `v-model` on the `RadioGroup` (a string or `null`), which emits `update:modelValue` only; a Radio inside it ignores its own `v-model` and `name`.

Tests ([testing.md](./testing.md)): `FormData` after toggling and one native `change`; reset restores the initial value; `required` blocks submit and focuses the control (the visible part of a custom control); a disabled `<fieldset>` disables the control; an input outside its `<form>` with the `form` attribute submits and resets with it.
