# Overlays in Vue

Shared rules: [overlays-and-positioning](../framework-agnostic/overlays-and-positioning.md#rules-for-every-framework-adapter). Why: [overlays](../../why/overlays.md).

- Overlay content renders through the one portal component in `@cocokits/vue-core`, which is the only `<Teleport>` in the Vue packages. There is no `<Teleport :disabled>` bound to a prop. `Portal` takes `open` and `getTrigger`, creates the cdk host in `onMounted` (and when `open` turns true), takes the mode names from the page collections of `ThemeConfig.modeCollections` and the direction from `useDirection()`, and renders nothing on the server.
- The direction is set with `provideDirection('rtl')` in `setup` or `provideDirection('rtl', app)` for the app, and read with `useDirection(propDir)` (prop, then provided, then `'ltr'`).
- The container is resolved in `onMounted` when the overlay opens, never in setup.
- Inside/outside decisions use registered refs (`rootEl.contains(target)` is wrong for portaled content). Communicate through emits and context: provide/inject crosses the portal, DOM events do not bubble through the Root's ancestors.
- A content part that takes focus renders its two focus guards as siblings of the content inside the `Portal` slot, and a content inside another content registers its dismiss layer as a child of the parent's, handed down with provide/inject under the one `DISMISS_LAYER_KEY` (`packages/vue/src/internal/dismiss-layer.ts`). Every overlay (Popover, Dialog, Tooltip, Select) uses this key, never one of its own, so overlays of different kinds nest.
- Start dismiss, focus handling and exit animation in a `flush: 'post'` watcher on the content's element ref and stop them in its cleanup.
- A modal content (`DialogContent`) calls `showModal()` in the same watcher, locks scroll with `lockScroll` while open and returns focus to the trigger a frame after the presence reported `unmounted` (the dialog is inert until it has left the document); a native `close` the parent refuses is shown again.
- The Select is a compound like the others: `SelectRoot` renders the root `div`, the hidden inputs and the validation message, and the author writes `SelectTrigger`, `SelectValue`, `SelectContent` and the items. The trigger keeps DOM focus while the list is open, and the items are mounted only with the list, so each item registers its DOM node through provide/inject and an opening key waits for them. No item registers a label for the Root to render: the trigger text comes from the Root's `items` or `itemToStringLabel`, so it is in the server render. The list lines up with the FormField's input wrapper (`inputWrapper` of the field context) when the trigger is the field's control. A multi-word listener of a machine (`onKeyDown`) is renamed with `toVueListeners` before it is bound, because `h()` and `v-bind` would turn it into the event `key-down`.
- Tests: [testing.md](./testing.md); server output is checked with `renderToString`.
- **Refuse a dismissal with the Content emits, the way Reka does.** `DialogContent` and `PopoverContent` emit `escapeKeyDown`, `pointerDownOutside`, `interactOutside`, `openAutoFocus` and `closeAutoFocus` (the Popover also `focusOutside`); `TooltipContent` emits `escapeKeyDown` and `pointerDownOutside`. They run before the overlay closes, synchronously, with the real event (a cancelable `CustomEvent<{ originalEvent }>` for a press or a focus move), and `event.preventDefault()` (or `.prevent`) in a listener refuses. The specific emit comes first, then `interactOutside` with the same event; a refusal in either keeps the overlay and every layer below open. A close with no key (the `cancel` event, a `<form method="dialog">` submit) calls no key listener; only a bound `v-model:open` that ignores the update refuses it. The root reports a change with `update:open` alone.
- The Trigger and Close parts send their click whatever a consumer `preventDefault()` did ([the exception](./data-attrs-and-anatomy.md#consumer-veto)).
- A Dialog opened by its Trigger returns focus to that Trigger; a Dialog opened another way (without a Trigger, a controlled `open`) returns it to its opener (the deep active element when it opened). A Dialog without a Trigger opens; a Popover or Tooltip without a Trigger warns in development.
- Overlay content extends the one `OverlayPositioningProps` interface (`packages/vue/src/internal/overlay-positioning.types.ts`: `sideOffset`, `alignOffset`, `avoidCollisions`, `collisionPadding`, `sticky`, `hideWhenDetached`). The content passes a prop to `startOverlayPosition` only when it is set, so the cdk defaults apply otherwise; the boolean props default to `undefined` (Vue casts an absent Boolean to `false`). `TooltipContent` extends it too. `TooltipProvider` is optional and renders no element: it sets `delayDuration`, `skipDelayDuration`, `disableHoverableContent`, `disableClosingTrigger` and `disabled` for the tooltips inside it, which share one skip window; a Root prop wins over it. The Popover Content and Anchor take `reference` for an element or a virtual anchor.
