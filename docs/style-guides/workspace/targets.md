# Nx targets and commands

The one list of the commands that exist. Skills and guides refer to this file. A check that is not listed here does not exist; do not substitute another check. Report a check that is not listed as `not available`.

## Project targets

| Target | Runs | Projects |
|---|---|---|
| `build` | Library build (`dependsOn: ["^build"]`). Most packages use `tsdown`, the Vue packages Vite, the Angular packages `ng-packagr` (through their `package` target). A tool project has no `build`: Nx runs its sources as they are | all packages |
| `typecheck` | `tsc --noEmit` on the lib and test configs | all packages and the tool projects |
| `lint` | Typed ESLint with `--max-warnings 0`; includes the module-boundary rule, the entry-point import rule ([nx-tags-and-boundaries.md](./nx-tags-and-boundaries.md)), the Angular contract rules (`tools/eslint/contract-rules.mjs`: no `cck-` class literal and no manual `addEventListener` or `removeEventListener` in Angular code; exceptions: [below](#lint-exceptions)), the `cycles` target and the file-size rule (no TS, TSX, JS, JSX, HTML, CSS, SCSS or Markdown file over 500 lines of code; HTML, CSS, SCSS and Markdown files are linted for that rule only) | all packages and the tool projects |
| `cycles` | `depcruise <projectRoot> --config .dependency-cruiser.cjs` (dependency-cruiser, run from the repository root): fails on an import cycle (`import type` included) and on an import into another component folder other than its entry. The rules and the component folders: [nx-tags-and-boundaries.md](./nx-tags-and-boundaries.md#rules); the config's comments name them in code. Cached on the project's files and the config; `lint` depends on it. The check itself is tested on fixtures by the `workspace:test` target (`tools/workspace-plugin/src/checks/dependency-cycles.spec.ts`) | `machines`, `cdk`, `angular`, `react`, `vue` |
| `test` | Vitest | all packages and the tool projects |
| `tokens` | Generates the theme's token stylesheet and, when the optional `modesOutput` option is set, a TypeScript file of mode lists and the modes index `modeCollections` from its token JSON (what it holds and how it is used: [theme-config](../themes/theme-config.md#values-from-token-collections)) (`@cocokits/workspace:tokens`); `input`, `output` and `modesOutput` are workspace-relative and must stay inside the workspace, also after resolving symlinks and junctions; `build`, `typecheck`, `lint` and `test` depend on it | `theme-cocokits` |

### Docs targets

| Target | Runs | Projects |
|---|---|---|
| `sync` | `astro sync` in `apps/docs` (generates `.astro`, the Astro types); depends on `^docs-data`, `^api-docs`, `api-parity` and the `stories` of the three preview apps; cached, output `apps/docs/.astro`; `lint` depends on it | `docs` |
| `docs-data` | Docs data JSON into the project's `src/generated/docs-data/` (`@cocokits/workspace:docs-data`); depends on `build` | `machines`, `theme-cocokits`, every theme core the generator makes |
| `api-docs` | API extraction into `src/generated/api-docs/`; fails on a public member without TSDoc. `angular`: the Angular compiler's docs extractor (`@cocokits/workspace:api-docs-angular`); `react`: the TypeScript checker (`@cocokits/workspace:api-docs-react`); `vue`: `vue-component-meta` (`@cocokits/workspace:api-docs-vue`). The three share `api-docs-common`; the target depends on `^build`, and its inputs add the machine `*.types.ts` files | `angular`, `react`, `vue` |
| `api-parity` | Compares the Angular, React and Vue `ApiDoc` files by semantic id (`@cocokits/workspace:api-parity`); failure and report rules in the [parity policy](../docs/api-extraction.md#pipeline); depends on `angular:api-docs`, `react:api-docs` and `vue:api-docs`; `sync` depends on it | `docs` |
| `stories` | The story compiler for the framework: the stories and their `StoryMeta` into `src/generated/stories/`; depends on `angular:api-docs` and `theme-cocokits:docs-data` (`preview-react` also on `react:api-docs`, `preview-vue` on `vue:api-docs`); `build`, `typecheck`, `test` and `dev` depend on it. Option `reporter` (`{ module, function }`) names the module and the function the run module of a story with component events calls to report each event to the Events panel; the compiler knows no `@cocokits/*` name, so each preview app sets it to `@cocokits/docs-shared` and `reportEvent`, and without it the run module reports nothing. It also checks each `*.scenario.ts` against its story and writes `<theme>/<component>/<id>.scenario.json` beside the story's JSON ([scenarios](../docs/scenarios.md)) | `preview-angular`, `preview-react`, `preview-vue` |
| `typings` | The typings of the story language into `src/generated/jsx.d.ts`; same dependencies; `lint` and `typecheck` depend on it | `docs-stories` |
| `build` (app) | `preview-angular`: Angular application build with `strictTemplates`, base path `/preview/angular/`, flat output in `dist/apps/preview-angular`. `preview-react`: Vite build, base path `/preview/react/`, flat output in `dist/apps/preview-react`. `preview-vue`: the same for Vue, base path `/preview/vue/`, flat output in `dist/apps/preview-vue`. `docs`: extraction, the `stories` and `build` of the three preview apps, `astro build`, the HTML check and the copy of the three previews into `apps/docs/dist/preview/<fw>/` | `preview-angular`, `preview-react`, `preview-vue`, `docs` |
| `dev` | `docs`: the extraction, the story compiler, the three preview dev servers (`preview-angular:dev`, `preview-react:dev`, `preview-vue:dev`, each started with `--port` set from the docs option), `docs:watch-data` and `astro dev` (options `--port`, default 4300, `--previewAngularPort`, default 4301, `--previewReactPort`, default 4302 and `--previewVuePort`, default 4303); needs the Nx daemon. `preview-angular`: its dev server through `serve`, option `--port`, default 4301. `preview-react`: `vite --port`, option `--port`, default 4302. `preview-vue`: the same, default 4303 | `docs`, `preview-angular`, `preview-react`, `preview-vue` |
| `watch-data` | `nx watch` over the sources of the docs data, the API, the stories and the typings, re-running their targets; needs the Nx daemon | `docs` |
| `preview` | Serves the built site (`astro preview`) | `docs` |
| `links` | Crawls the built site and fails on a broken internal link | `docs` |
| `lighthouse` | Lighthouse (mobile preset, 3 runs, the median run counts) on Welcome and the Button Overview against the budgets of `apps/docs/src/config.ts`; the built site is served gzipped, like a real host | `docs` |
| `check` | The consumer fixture (`@cocokits/consumer-fixture:check`): packs every package the generated stories import (`pnpm pack`, `workspace:*` resolved), installs the tarballs into a temporary project outside the workspace with no registry (`pnpm install --offline`), and compiles the shown code of every story of each framework there (every `files[].code` from the story's `.json`, written under its `files[].name`, the React `.css` file of a story with styles included, with the registry that imports it; the run module, which a preview app's build compiles, is not among them) with `ngc` (`strictTemplates`), `tsc` and `vue-tsc` (`strictTemplates` with `checkUnknownProps` off, as Reka UI components need: [Reka issue 2875](https://github.com/unovue/reka-ui/issues/2875)); the temporary folder is deleted at the end (option `--keepTemporaryProject` keeps it). The offline install needs a pnpm store primed by `pnpm install` first; a package missing from the store fails the install. Not cached, not run by `affected`, not in CI; depends on `build` of the Angular, React, Vue and theme framework packages and on the `stories` of the three preview apps. Why: [tooling](../../why/tooling.md#the-consumer-fixture-is-built-once-for-all-frameworks) | `consumer-fixture` |
| `typecheck` (docs) | `astro check` | `docs` |
| `browser-facts` | Playwright Test in real Chromium over the timing premises of the story compiler the cdk platform facts (`browser-facts/cdk-rows.ts`: registered `--side-offset`, CSS animation lists, a popover host moved into a fullscreen element) and the overlay facts of its design (plain DOM: `popover="manual"` host in a modal dialog, no clipping, Escape routing, iframe containment, focus return; `browser-facts/overlay-rows.ts`) the focus origin of a dialog opened with `CckDialog.open` (`browser-facts/service-focus-origin.spec.ts`: after Escape the opener matches `:focus-visible`, after a backdrop press it does not), and over stories it prints, run in Angular (no zone), React and Vue built from the workspace (`browser-facts/`, no server); the configuration `all-browsers` (`pnpm nx run story-compiler:browser-facts:all-browsers`, `browser-facts/playwright.all-browsers.config.ts`) runs only the dismissal rows (`browser-facts/dismissal-rows.ts`: Escape phase and repeated Escape, `cancel` and the close watcher, backdrop and scrollbar presses, touch) in Chromium, Firefox and WebKit; the scrollbar row is skipped on a host that draws overlay scrollbars (one-time download: `pnpm exec playwright install firefox webkit`); depends on `^build`, `api-docs` of Angular, React and Vue and `docs-data` of the themes like `test`; not cached and not run by `affected` or CI (it needs a browser, like `e2e`). It is a required check of a change under `tools/story-compiler`: the [reviewing-code](../../../.claude/skills/reviewing-code/SKILL.md) check table names it. One-time browser download as for `e2e` | `story-compiler` |
| `e2e` | Playwright Test on the built site: real key presses and layout checks in Chromium (the Tab order of the chrome, the skip link, the Modes panel, the Workbench and its full-screen dialog, the anatomy explorer, the contents, the sticky app bar, the scrolling regions, a switch used before the page scripts have run, the overlays: the anatomy explorer outlining a portaled part, an open start, a clipped container, a colour-mode change while open, and the Popover contract), and every story scenario in the three frameworks ([scenarios](../docs/scenarios.md)). It depends on `docs:build` and serves `apps/docs/dist` with `apps/docs/scripts/serve-dist.mjs` on port 5130 (`DOCS_E2E_PORT` changes it). The configuration `overlays` (`pnpm nx run docs-e2e:e2e:overlays`, `apps/docs-e2e/playwright.overlays.config.ts`) plays only the scenarios of the Dialog, Popover, Tooltip and Select (`SCENARIO_COMPONENTS`) in Chromium, Firefox and WebKit. One-time browser download: `pnpm exec playwright install chromium` (`firefox webkit` for the `overlays` configuration); `CHROME_PATH` names another Chrome. Where the tests live: [testing](../testing/index.md#end-to-end-tests) | `docs-e2e` |

`test` and `lint` of `docs`, `preview-angular` and `docs-stories` are the inferred Vitest and ESLint targets (`docs-e2e` has `lint` and `typecheck` but no `test`: Vitest never runs its files); the Angular contract lint (no `cck-` class literal, no manual listener) also covers `apps/preview-angular`. The generated `src/generated/` folders are git-ignored and are the Nx outputs of the targets above.

Run one target on one project with `pnpm nx run <project>:<target>`, for example `pnpm nx run machines:test`.

## Lint exceptions

A lint exception is never a disable comment (`eslint-disable`). A file with a justified use of a banned pattern is an entry in `tools/eslint/exceptions.mjs`: its files, the rules it turns off and a one-line reason. A test file is listed the same way, with its reason. A folder ESLint must not read at all (the fixtures of the cycle check) is an `IGNORED` entry in the same file, with its reason. A part's manual listener also needs a row in the [host-bindings exceptions table](../angular/host-bindings-and-data-attrs.md#exceptions) first. Why: [tooling](../../why/tooling.md#lint-exceptions-live-in-one-file).

## Workspace commands

| Command | Runs |
|---|---|
| `pnpm nx format:check` / `pnpm nx format` | Prettier over the workspace (also `pnpm format:check`, `pnpm format`) |
| `pnpm nx affected -t lint typecheck test build` | The local set (also `pnpm affected`) |
| `pnpm ci:local [--base <ref>] [--title "<PR title>"] [--all]` | The whole GitHub pipeline locally; run before every PR push: [ci-pipeline.md](./ci-pipeline.md#pnpm-cilocal) |
| `pnpm nx run-many -t lint typecheck test build` | The same for every project (also `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` one target at a time) |
| `pnpm lint:files` | ESLint (`--max-warnings 0`) over every linted file type (TS, TSX, JS, JSX, Vue, HTML, CSS, SCSS, Markdown) outside the Nx projects: root configs, `tools/eslint/`, `tools/scripts/`, `docs/`, `.claude/`, `.github/`, `.changeset/`. `apps/**`, `packages/**`, `tools/workspace-plugin/**`, `tools/story-compiler/**` and `tools/consumer-fixture/**` are covered by their project `lint` targets. Run by `pnpm ci:local` |
| `pnpm changeset add` | Add a changeset |
| `pnpm nx g @cocokits/workspace:library` | The library generator ([generators.md](./generators.md)) |

## Git hooks

- pre-commit: lint-staged runs ESLint and Prettier on the staged files only (Markdown, HTML, CSS and SCSS get the file-size rule).
- commit-msg: commitlint checks the message.

## Target defaults

`nx.json` sets caching and `dependsOn` for the targets above: `build` depends on `^build`, `typecheck` and `test` depend on `^build`. Every `package.json` declares its workspace dependencies so the `^build` graph is complete. Nx Release is not used; Changesets owns versioning.
