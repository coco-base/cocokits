# Form participation

Shared rules: [cdk-modules](../framework-agnostic/cdk-modules.md#form-participation). Contract: [architecture](../../architecture.md#6-props-events-and-forms-contract).

- A custom visible control (not a native choice control) activates a hidden input with `inputRef.current?.click()`; the input's `onChange` is the only place state changes.
- **Rejected controlled changes** (hidden input): the input is a controlled React input, so when the parent keeps the old value React restores the input; `FormData` never shows a value the component does not render.
- **Owner form, reset, fieldsets**: a small hook wraps the cdk form-control module's responsibility for this (this guide fixes no API names). Cleanup is idempotent and StrictMode-safe.
- **Native control** (`Input`, `Textarea`, `Checkbox`, `Switch`, `Radio`): there is no hidden input and no `click()` forwarding. Given `value` (`checked` for a choice control) it is controlled, and a change the parent rejects is restored. Without it, it is a native uncontrolled input (`defaultValue`, `defaultChecked`) and the DOM is the source, so a value written through the ref (react-hook-form `register()`) survives re-renders; DOM-derived facts (`filled`, `data-checked`) are read from the element in the layout effect and on events. The form hook (`useFormParticipation` from react-core) reports reset, submit and fieldset, in its checked mode for a choice control. A choice control reports a user change from the native `change` event of its input, puts `ref` on the input (`className`, `style`, `hidden` and `render` belong to the root), and a read-only one cancels the click. The radio group uncheck is in [architecture §6](../../architecture.md#6-props-events-and-forms-contract). The `RadioGroup` owns the value of a group of Radios (`value`/`defaultValue`/`onValueChange`); a Radio inside it ignores its own `checked` and `name`.
- **Custom control with a `button` trigger** (the Select): the button is the `elementRef` of `useFormParticipation`, so the reset, the submit attempt and a disabling fieldset reach it. Its hidden inputs are `type="text"`, not `hidden` (a hidden input is barred from constraint validation), with `tabIndex={-1}`, `aria-hidden` and no class; an `invalid` event on them returns focus to the trigger and is never canceled (a canceled `invalid` lets the submit go on).
- React Actions work unchanged: `<form action={...}>`, `useActionState` and `useFormStatus` read values from `FormData`.

Tests ([testing.md](./testing.md)): `FormData` after toggling; `checkValidity()` with `required`; reset restores the default; a disabled fieldset disables the control; the `form` attribute re-targets the owner; `readOnly`/`disabled` do not toggle; a rejected controlled change leaves `FormData` unchanged.
